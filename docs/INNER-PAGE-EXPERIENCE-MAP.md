## Forensic baseline

The current implementation already preserves the seven original homepage routes and their slide media. It also provides source-qualified long-form copy, verified Work matching, related capability links, direct-route static fallbacks, canonical metadata and adjacent journey links.

The red-team design issue is structural rather than factual: six routes share a similar long-form numbered-list treatment, while Metaverse has a separate long-form treatment. The content is correct and crawlable, but the route bodies do not yet create sufficiently different **discovery behaviours** after the entry field. This phase addresses that without altering homepage DNA.

## Narrative architecture

Every route follows Angel’s shared journey without becoming a repeated template:

```text
ENTRY FIELD
  → ORIENTATION / WHY
  → ROUTE-SPECIFIC EXPERIENCE MAP
  → PROGRESSIVE APPLICATION EXPLORATION
  → WHAT IT CAN BECOME / VERIFIED WORK
  → DISCIPLINES BEHIND IT
  → WHERE NEXT?
  → CONTEXTUAL PROJECT PROMPT
```

The shared elements are the dark environment, source-slide media, number edge, warm accent, thin rules, controlled reveal, normal scrolling and existing navigation. The map vocabulary, application interaction, content density, capability subset and CTA wording differ by route.

## Content source and integrity

- The approved long-form copy is the authoritative content for all seven routes.
- Every possible use case remains framed as can, potential, possible, applications include, or equivalent approved language; it is not represented as delivered Angel work.
- Work remains limited to the verified 47-record archive and exact published-title matching.
- No client, result, award, team, industry proof, testimonial or case-study outcome is introduced.

## Interaction constraints

The experience maps and application explorers must:

- reveal information rather than decorate;
- be usable with mouse, touch and keyboard;
- retain a complete semantic no-JavaScript static counterpart;
- keep all critical copy crawlable;
- use the user’s route-specific vocabulary;
- use 150–350ms interaction feedback and no forced wait;
- defer media rather than add new media weight.
